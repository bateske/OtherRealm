# Title and pause presentation

Normal startup always shows a 128×128 title. Any button opens Continue/New Game
when a valid checkpoint exists; with no save it starts the intro immediately.
New Game confirms replacement when needed and starts part 16001. Start during
that intro offers Skip Intro, which enters part 16002. The original disk save
is replaced only after a valid playable checkpoint, never halfway through the
intro. The old Watch Intro menu entry has been removed.

The default title is the shoreline with Lester fully standing after his climb from the pool, filling
the entire 128×128 panel. Completing the game permanently unlocks the alternate
title of Lester facing the camera and raising his hand. Both scenes stay on SD;
only the chosen title is loaded. The shoreline replay releases swim input when
the exterior starts and waits for the settled standing pose at task 20 PC 0x22F0
(tick 170 on these disks). The capture tool validates its control-handoff anchor;
it also checks the greeting scene's
bytecode anchor and composes its polygon resources with Lester lowered to leave
room for the title. The foreground guard is omitted to keep his raised hand
visible. Both captures draw at 208×130 and crop the central 128×128; pixels are
not enlarged and gameplay's camera/scripts are unchanged. The public demo has
its own authored background, generated by the same capture tool.
The separate OTHER REALM bitmap has original angular black letterforms with a
thin gold outline, hand drawn at native resolution. Its outlines are CC0 and
require no external font. `tools/title_art.py` is its source recipe;
`engine/aw_title_art.h` and `assets/title.png` are generated outputs.

To produce the private title from the user's disks, after `build-host.ps1` and
the normal 104×65 extraction/text patch:

```powershell
python tools/build_pack.py AnotherWorld_DiskA_nologo_noprotec.adf AnotherWorld_DiskB_nologo_noprotec.adf --width 208 --output private/title/source.pak
node build/capture_title.js private/title/source.pak private/title/shore.bin shoreline
node build/capture_title.js private/title/source.pak private/title/greeting.bin greeting
python tools/patch_title.py private/handheld/OTHERWRL.PAK private/title/shore.bin private/handheld/OTHERWRL.PAK --unlocked private/title/greeting.bin
```

`patch_title.py` validates before replacing a pack, is idempotent, preserves
resource IDs and save identity, and keeps a custom scene directory last. The
type-10 default and optional type-11 unlocked resources are each exactly 8,224
bytes: sixteen little-endian RGB565
colors, followed by 8,192 bytes of 128×128 packed pixels (high nibble first).
Only this private pack contains the original game's title scenes. It is excluded
from source and cartridge distribution. Packs without a title resource remain
playable and show a simple fallback backdrop.

At boot, the renderer borrows its existing four pages for this title. Starting
or continuing calls `Game::begin`, clearing all pages before VM execution.
Pause retains the actual game frame and palette, dims a cached 16-color
palette (32 bytes of RAM), and overlays centered native-size menu glyphs. The
repeated game-name heading is removed; only confirmation/death context remains.
The selected text is warmer and brighter. A breathing glint sweeps back and forth
across it, taking 7.68 seconds per direction. Cyan/gold motes form across a broad
area around the glint, grow gently, and drift down as far as about 42 pixels.
Changing selection releases fifteen dust motes around the new label, while the
nine ambient particles keep running. Confirmation uses ten motes. The ambient
and transient effects have separate slots, so a dust cloud never interrupts the
falling sparkles. Twenty-four two-byte positions use 48 bytes; trajectories are
computed once per screen, and appearance is derived only on rows they touch.
There is no heap allocation or simulation during gameplay.

Confirming a choice that leaves the menu first spends about 672 ms sending motes
upward with varied horizontal velocities and mild gravity, while fading the other
options into the scene and retaining the selected text. Then the chosen line fades
away over about 192 ms, without moving. Sound toggles emit the same soft poof while
keeping every option visible. The checkpoint status remains centered and stationary.
A/B button letters are brighter than their labels. B in
Continue/New Game returns to the title without running the VM or writing a save.

Opening fades in over about 192 ms; gameplay stays frozen until closing finishes. There
is no selection slab or divider. Closing streams the undimmed game frame and
letterbox margins in one pass, without clearing the panel to black first.
The title prompt has no background strip and pulses between white and the
scene's blue-gray (RGB565 0x42B0) over 7.68 seconds. No extra screen buffer is
required. An absent unlocked title falls back to the ordinary title.

There is no Exit menu item. Holding Start for three seconds returns to the system
launcher from title, menus or gameplay, using elapsed milliseconds independently
of VM timing. A thin 96-pixel bar at the top appears after about 313 ms and fills
until exit; releasing early cancels it. A tap still pauses/resumes. On the title,
a short Start press activates on release so a long hold never starts a game.
The bar shares the row painter and needs no additional pixel buffer.

Completion is recorded when the original game enters its noninteractive final
escape/credits part (16007). Authored games can emit system event 3 instead.
The flag survives new games and checkpoint replacement, using one previously
reserved bit in the existing 44-byte save record. Existing saves still load.

Sound defaults on and can be toggled in the menu. These are lightweight piezo
cues for menu actions and script sound events, not the original PCM samples or
soundtrack. The original tracker still advances synchronization events. The
browser uses short synthesized tones after an input gesture. The device uses
CHGame's Apache-2.0 piezo sequencer on PB10/TIM1; its license and notice are
included. The combined device binary is distributed under GPL-3.0-or-later;
the portable engine's GPL-2.0-or-later grant remains unchanged. Sound preference
lasts for the session and defaults on again after power-up.
